# 方法核对及后续写作边界

## 已锁定的分析口径

| 环节 | 主检验家族 | 其他口径 |
|---|---|---|
| 饮食–CGM（15） | 每队列/模型内按暴露角色分80、40、20次检验 | 全局140、每饮食20及HC3等为已有敏感性；不能误写全部主分析统一140次BH |
| 菌–CGM（16a） | 每个结局/模型集合内379菌 | 每模型集合全局7580为敏感性 |
| 单菌中介（18） | 每饮食×结局内冻结的菌集合 | 全局1490为已有敏感性；本包不重算 |
| 三模型整合（18f） | 继承各模型原判定 | primary稳健、strict/protocol稳健的交集；不是新的独立检验 |
| Step20–23 | 描述性汇总与数据核查 | 没有新P值或FDR，没有独立路径富集检验 |

上述来自本地15、16a、18b、18f代码。新包记录服务器实际使用文件的哈希，不把本地代码存在当作服务器运行证明。

分析样本复原沿用18b/18c/18e2逻辑。基础协变量为age_years、sex、education_level、smoking_status、sleep_duration_hours_day、physical_activity_met_h_week、vitamin_use、hormone_use、bmi、cgm_device_type。hPDI另加alcohol_intake_g_day，EAT13/NOVA4/Carbohydrate_pct另加mean_daily_energy_kcal；protocol再加饮食记录窗口的抗生素/PPI。饮食缺失、结局缺失、菌值缺失及必要协变量缺失逐路径处理。

主样本纳入“排除标志不等于1”，其中可能包含排除状态未知；strict只纳入标志等于0。缺少整个协变量记录的人不能当作“排除标志未知且可纳入”。程序对4470个模型路径核查N及完整病例ID的SHA256，不输出参与者ID列表。

## 完成后可引用的材料

- 原871路径不变，完整1490×3模型结果可作为补充表；每路径有原效应、CI、N和校正结果。
- 领域必须同时报告指标数及分母。598条波动路径不等于598次独立重复，也不能仅凭比例称“富集”。
- full20、no_GMI19、concept_panel9并列；9项面板按概念涵盖水平、相对/跨天/日内变异、低/高风险及两个复合指标，为看到结果后的描述性选择，不声称预注册。
- 代表性森林图的路径来自冻结结果，并记录全部选中行；既展示COGI不同解释方向，也展示E. rectale在NOVA4/hPDI同结局的对照。
- 总效应绝对值≤0.01只作为可追溯的描述性提醒阈值（既有Z尺度），不是统计检验。全部路径仍在完整补充表中。

## 尚不能写成已证实

历史IGLU版本与参数、SDw新增处理过程若缺记录，保留待核实。逐路径N和样本哈希一致证明样本身份一致，不证明历史参与者数值完全相同，因为旧18b清单未保存全部表型输入的历史哈希。

同队列先筛选再进行中介分析，bootstrap并未自动包含整个筛选流程的不确定性。严格样本和药物敏感性与主样本重叠，应称敏感性支持，不是独立验证。不要将事后划分训练/测试集写成独立外部复现。

不同菌的单中介估计并非可相加的独立贡献。不能把总效应近零时的不稳定中介比例作为主要结果，也不能在方向不一致时强行解释为“解释了X%”。

缺少纵向顺序、功能/代谢物测量和外部验证时，Discussion用“与……一致”“提出待验证假设”，不用“饮食通过某菌改善/损害血糖”的确定因果结论。

## 后续人工收尾

读取服务器摘要后，先处理所有FAIL/REVIEW_REQUIRED，再根据真实相关矩阵和保留率完善Results。机制证据按完整taxonomy、菌株、底物、设计和结局逐项核对，之后才决定主文与补充材料布局。参考文献起点已列入文件，不代表全部109菌的系统综述已完成。
