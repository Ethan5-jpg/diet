# 记录覆盖与餐后时间分段：实施计划

Goal：在上一轮七项饮食结果之上，检验记录覆盖敏感性，区分早期/晚期餐后关联，并整理调整前后及峰值结果。
Architecture：只读取原 meal run、seven run、饮食日期汇总和原 SQLite 缓存。复用冻结的评分、样本与模型函数；所有新文件进入独立输出目录。
Tech stack：Python >=3.8，现有 numpy/pandas/scipy/matplotlib/sqlite3；不增加依赖。

用户已授权本轮规划、实现、测试及交付；在当前文件夹连续完成，不另建工作任务或委派代理。

1. inputs.py：固定依赖哈希，核验旧运行与评分来源，检查 diary 日表，保留字符串身份。测试重复、日期、时区、源文件改变。
2. coverage.py：按原连接重算合格餐曲线；日覆盖采用完整本地日、15分钟时间格及夏令时实际日长。内部空日进入分母，多连接日排除。验证原基线/iAUC/峰值并分成0–60和60–120分钟。
3. analysis.py：复现原主样本42规格与成员哈希，再运行 aligned/cgm90/log80/joint 和 joint_people_all_meals 各42规格。原时间特征在筛选前固定；七项全报告。
4. 时间分段：原主样本和joint分别估计7评分×早期/晚期/晚期减早期，共42规格。每组21项FDR。其余每组按旧规则三家族各14项。所有不可估计规格保留。
5. reporting.py：汇总日记录交集、样本流失、保留/排除人群、峰值及调整变化和时间段森林图；不以显著性选择结果，不输出个人身份到公开表。
6. run_analysis.py / run_quality_timecourse.sh：启动、check、show、失败状态、源文件运行前后哈希检查；一个文件夹整体上传。
7. tests：DST、空日、重复冲突、日界线、传感器重叠、饮食日期缺失、配对人群、模型复现、分段积分恒等式、失败输入、全空模型、合成端到端及旧包回归。

预先固定的操作性敏感性阈值（非官方标准）：CGM完整参考日有效时间格>=90%；个人至少7个完整无歧义CGM参考日，其中>=80%日期存在同日且同时区饮食汇总。阈值仅考察记录覆盖，不能确认无漏餐。不能把食物条目数当餐数，也不按热量/条目数筛选。

对照六组：source_primary；aligned（匹配完整CGM日、日表、时区）；cgm90；log80；joint；joint_people_all_meals（每个评分/分支joint保留的同一批人，取他们原来的全部合格餐）。后五组是重叠样本敏感性，不是独立验证，不合并成一个总FDR结论。

早晚结果均为相对原餐前基线的平均净增量，允许负值，单位mg/dL；早晚差用直接差值模型，不比较两个P值。调整前后只报告系数变化，不解释为机制或中介比例。

参考：[HPP饮食日志](https://knowledgebase.pheno.ai/datasets/005-diet_logging.html)、[HPP CGM](https://knowledgebase.pheno.ai/datasets/017-cgm.html)。完整参考日取传感器实际观测跨度，不等同于外部确认的佩戴计划。
