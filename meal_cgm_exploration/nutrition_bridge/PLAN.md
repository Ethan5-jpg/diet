# 营养调整、正增量与整体 CGM 衔接

日期：2026-09-26。状态：用户已同意构建；未查看本轮真实数据结果。

Goal：解释现有调整前后关联变化，检查净面积抵消，并把餐次特征与原20项整体CGM联系起来。

Architecture：独立包，只读原 meal / seven / quality 输出；复用冻结的输入、样本及 HC3 / 个人固定效应 CR1 实现。所有新输出写入独立时间戳目录。保留七项评分原方向与原Z单位。

Tech stack：Python >=3.8；numpy、pandas、scipy、matplotlib；不增加依赖。

## 固定分析范围

1. 原始主样本 source_primary 和联合质量样本 joint；先复现两套共84项旧模型，包括成员哈希、系数、标准误、区间和q值。
2. 个人平均反应 A：固定各评分原合格样本，依次并列背景、加平均餐能量、加平均餐碳水线性、同时加两者、再加餐碳水平方的平均值。不是平均碳水再平方。原有背景中的个人日能量及hPDI酒精调整保持。两核心结局×七评分×五模型×两样本=140项；每样本70项探索家族BH校正。
3. 每一模型提供焦点评分剩余方差比例、VIF、最大杠杆值、最大Cook距离、单人删除引起的最大系数变化。提供评分与餐营养的原始/背景残差相关。不据此自动删人，不计算中介比例，不把条件数单独当作共线性结论。
4. 正增量=原 iauc_positive_0_120/120；七评分×(A背景、A餐次调整、B碳水交互)×两样本=42项；每样本21项独立探索家族。人和餐与旧模型完全相同。任一所需餐的正增量缺失时该规格明确不可估计，禁止静默删餐。数值非法、负值或正面积小于净面积则停止。报告零值、分布及正净差；与旧系数变化仅作描述。
5. 原20项整体CGM：使用既定最终表原Z列，不重新计算20项。访视、队列、连接编号匹配；不以任何饮食评分或菌群完整性筛人。每人至少5餐/3日，协变量和原两核心餐结局完整；正增量个人均值要求其全部合格餐均有值。对每项整体CGM与三项个人餐特征做背景调整HC3回归（餐特征每1个配对样本SD，整体CGM原Z单位），另列原始Spearman相关、独特值数、人数及成员哈希。20×3×2=120项，每样本60项BH；Mean/CV/MODD/SDw为既定重点，全部20项报告。少于50人、少于3个不同结局值等保留不可估计行；不因结果选择结局。

整体CGM与餐次指标共享部分读数，属于同一观测期的关联衔接，不是独立验证。跨表以同连接限制避免混传感器；并不声称整体统计仅覆盖合格餐日期。SDw标注为日内SD的跨日平均。GMI与Mean可能高度冗余，不算两条独立发现。

## 文件与检查

- inputs.py：冻结依赖、输入与原输出哈希；核对原始来源和两套成员；匹配正面积与整体CGM。
- analysis.py：样本复现、调整诊断、正面积及20项衔接；记录全部计划规格与失败原因。
- reporting.py：总表、简洁终端分页、静态图、摘要；无参与者身份出现在汇总表。
- run_analysis.py / run_nutrition_bridge.sh：单命令入口，失败/中断留记录，不覆盖原结果。
- tests/：统计计算独立参照、成员/访视/连接核验、缺失及空样本、多重校正、篡改检测、合成全流程及截图分页。
- REVIEW.md：实际检查记录；明确合成检查不能证明真实结果有效。

默认整体CGM源沿用本地已归档的服务器路径 run_20260919T030229_482714Z_c1a0f480；找不到时清楚报错，接受 --cgm-file 显式指定；不自动选择最新文件。

实现顺序：先输入/统计模块，再报告/入口，再有意义的合成和独立统计检查，最后冻结上传清单、复核旧文件未变，并给出单行服务器运行和分页命令。
