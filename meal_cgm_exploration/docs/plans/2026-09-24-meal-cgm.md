# HPP Meal CGM Implementation Plan

**Goal:** 构建可上传服务器的独立探索包，完成原始数据核查、餐次聚合、两小时餐后血糖计算、个体内 NOVA4 关联及有限菌群交互。

**Architecture:** 原始文件只读；分块导入运行目录的 SQLite 缓存，逐参与者/访视处理，避免把所有人的 CGM 同时读入内存。audit、build、analyze 可分别执行，保存配置、输入指纹、阶段状态和明确的失败原因。服务器运行不依赖本地绝对路径，不改变原分析。

**Tech Stack:** Python 3.8+，pandas、NumPy、SciPy、matplotlib、SQLite（标准库）；pytest 仅供开发测试。

用户已在本对话授权规划并实施，因此在本窗口完成代码与验证，不另设实施批准步骤。项目无 Git 仓库，不建立无关仓库或 worktree。

## 实施顺序

1. `config/default.json`、`hppmeal/common.py`：冻结默认规则、校验配置、严格识别身份和带时区时间；测试混合偏移、非法时间和 CSV 字段。
2. `hppmeal/ingest.py`：饮食与 CGM 分块落盘、NOVA 映射、来源审计；重复文件及冲突读数留痕，不从文件名伪造缺失字段。
3. `hppmeal/meals.py`：按整餐起点限制聚合跨度，保留缺失营养信息、前后进食距离、严格重复食物签名；测试跨块、跨日和零热量饮料。
4. `hppmeal/cgm.py`：逐连接计算严格餐前基线、两小时净面积及正面积、观测峰值、窗口质量；解析三角曲线与交叉零点，测试缺口和多连接。
5. `hppmeal/models.py`：参与者/访视固定效应、按参与者聚类的不确定性、样本门槛、NOVA 单位、有限交互及完整检验家族；对照显式虚拟变量模型验证数值。
6. `hppmeal/pipeline.py`、`hppmeal/report.py`、`scripts/run_pipeline.py`：阶段运行、状态摘要、服务器保留的明细与适合截图的汇总、无个人标识示例图。
7. `tests/`：合成数据端到端测试，失败路径及 Python 3.8 语法检查；本地示例只能验证缺少字段时不会产生伪结果。
8. `README.md`、`docs/分析规则.md`、`docs/本地验证记录.md`、`run_server.sh`：一键入口、恢复运行说明、输入/输出字典与本地实际验证记录。

## 首版范围

主暴露为每餐观察到的 NOVA4 能量/整餐总能量，分类能量覆盖至少 80%；95% 为敏感性。主结局为净增量面积，最大观测升幅为次结局。限定记录窗、餐间隔、有效覆盖和重复餐次数；这些阈值为探索性工作规则，不冒称已验证标准。

首版实现餐后两小时，不自动做四小时机制推断、因果中介、所有菌扫描、hPDI 每餐评分或机器学习。餐次重复性和时段仅作描述；同期菌群的交互明确为关联，取样日期不足时标记未知。

## 完成标准

- 一套命令在合成输入上跑完全部阶段，输出带 SYNTHETIC 标记，生产结果目录保持为空。
- 已知曲线的面积、缺口拒绝、时区对齐、重复食物聚合及回归系数通过实质测试。
- 输入缺失或语义待核实时明确输出 FAILED / REVIEW_REQUIRED，不报告成功模型。
- 每次运行使用新目录；分阶段恢复核对配置与输入，不误用陈旧缓存。
- 不下载服务器原始数据；不将测试数值或图解释为 HPP 真实结果。
