# 再次复核：上传前补漏

日期：2026-09-24。当前版本：**2026.09.24.3**。

结论：本轮发现的错配和运行状态问题已修复，可以上传当前整个文件夹，先执行 check、build。尚未在服务器真实全量输入上验证；模型是否具备研究条件，需要真实数据的检查结果和时间字段说明。

## 本轮发现并修复

1. **协变量、菌群可能跨访视错配。** 原先只按参与者编号连接，现在先核对队列和访视，再检查每人唯一性。兼容既有协变量脚本输出的 `cgm_research_stage`。其他访视和缺失身份分别计数；整列访视元数据缺失时暂停模型，不猜成基线。新增两份 scope 汇总供核查。
2. **最后校验失败可能遗留成功状态。** 分析计算返回后，如果来源文件已变化，现明确标记本阶段失败；拒绝被改动餐次表的恢复请求时，也不提前改写时间确认配置快照。
3. **中断和并发缺少完整保护。** 增加运行目录进程锁，阻止同时写入；每阶段一开始就将摘要更新为 RUNNING，键盘中断明确标记 INTERRUPTED。强制终止可能留下 RUNNING，应新建运行。终端展示工具遇到未完成或失败阶段，不展示残留结果表。
4. **已指定但不存在的取样日期文件曾被当成正常未提供。** 现在快速检查标出模型资料未就绪；分析时明确失败。只有配置为 null 才表示主动不提供日期、时间先后未知。

这些改动不改变餐次聚合、两小时面积、NOVA 暴露或预定模型公式。新增模型资料要求只用于防止错误连接。

## 仍需服务器数据确认

- 进食时间字段是否代表实际食用时间，以及补记时保存的时间含义。默认确认开关仍为 false，不能直接视为已核实。
- 真实数据中时间、营养、NOVA 映射、CGM 窗口以及协变量的有效覆盖；完整可用人次是否足以估计模型。
- 协变量和菌群的队列、访视字段是否随导出保留，两个菌列是否唯一匹配。check 检查表头，analyze 才核对具体行值。
- 粪便采样日期相对餐次的先后。同属一次访视不等于先采样后进餐；默认未提供日期，不称为“基线菌群预测”。
- 服务器 Python 依赖、可用磁盘、全量运行时长。check 报告磁盘余量，但没有依据本地小样本承诺全量资源需求。

## 上传与执行

上传整个最新版 `meal_cgm_exploration` 文件夹。在服务器文件夹内，使用此前 HPP 的研究环境：

```bash
bash run_server.sh --data-root /home/ec2-user/Desktop/HPP/Data --stage check
bash run_server.sh --data-root /home/ec2-user/Desktop/HPP/Data --stage build
```

先看 check 的 `build_ready` 和 `model_input_headers_ready`，再看 build 的 SUMMARY.md、餐次筛选和曲线。实际进食时间核实后才执行 analyze，完整步骤见 README。代码版本更新后，先前版本的运行不能直接恢复，应新建运行。

四小时曲线、正式重复性 ICC、进餐时段因果分析、因果中介等仍未纳入首版，不应把首轮探索包完成理解为这些研究问题已经解决。
