# 七项饮食变量与餐次血糖：实现计划

**Goal:** 用原七项个人饮食变量回答平均餐后反应差异和个人内碳水斜率差异，供服务器一次运行。
**Architecture:** 单独模块复用旧 BUILD 餐次表、原协变量及规范评分来源；新目录输出，不修改旧模型或数据。
**Tech Stack:** Python 3.8 兼容语法，numpy/pandas/scipy/matplotlib，沿用现有环境。用户已授权编写和自审，直接实施。

## 固定问题与实现

1. `inputs.py`：读取并核查原成功运行、餐次 SHA256、原代码指纹、协变量哈希；读取 current4 中 AHEI/AMED/rEDIH、单独 corrected hPDI、15d0 中 EAT13/NOVA4/Carbohydrate_pct。检查 ID 唯一和可用范围；评分保留原 Z 单位，不按餐数重新标准化。启动先逐项检查所有必要文件与字段。
2. `models.py`：A 分支每人一行，结局为合格餐的平均净增量和平均峰值升幅，HC3；M1 调整个人协变量及平均餐前/时间背景，M2 再加平均碳水、碳水平方和总能量，使用相同完整样本。至少 5 餐及 3 个日期。每人等权，不能把此分支称为个人内饮食评分变化。
3. B 分支个人固定效应：餐次碳水/10g、平方、总能量、餐前基线/趋势、时刻正余弦、前餐间隔、观察日和餐次时长，加个人饮食 Z×碳水/10g。个人特征的水平主效应被吸收；额外加入年龄、BMI、性别及评分特有协变量与碳水的交互，控制这些斜率差异。至少 10 餐、3 个日期、个人碳水范围至少 30g。人均总权重为 1，以人聚类 CR1；固定效应计入残差自由度。输出焦点交互及完整系数和诊断，不估计被固定效应吸收的饮食主效应。
4. 三套样本：primary_available（各评分可用样本）、strict_available（明确无糖尿病/A10标记）、primary_common7（七评分及酒精/日能量均完整的共同人群）。同一分支的共同样本按所有模型必需字段定义，保证七项的模型样本哈希一致；不据显著数量给评分排名。
5. 两项结局均为 mg/dL：mean_increment=net_iAUC/120、peak_rise。主检验家族为 A-M2 主结局 7 项+B 主结局 7 项，共 14；峰值另 14；A-M1 两结局合计 14 作背景模型家族。每套样本单独 BH；无法估计仍保留计划分母。共 3×42=126 个规格，全部报告。
6. `reporting.py`：七评分描述与配对相关（带 N）、样本流量、平均餐后表型描述、全部系数及诊断、三套样本稳健性对照、主效应和斜率差异森林图；中文摘要列全七项而不是只列显著项。估计值保留真实单位和原 Z 方向。图/表仅汇总，ID/完整分析输入只写 private。
7. `run_analysis.py` 与同文件夹 `run_seven_diets.sh`：--stage check/all、--show；精确默认路径，所有错误清晰说明；新输出 seven_diets_<UTC>；运行前后核对输入/源码；源输出只读。不依赖 followup 模块。
8. `tests/test_analysis.py`：真正检验合成已知参数、FE 与显式虚拟变量参照一致、每人权重、FDR 分母、共同样本、不足样本、修正 hPDI 选择、重复 ID/错误访视/源文件变更拒绝、端到端旧结果不变。做外目录/含空格路径启动检查、打包清单校验和 Python3.8 AST 检查。

## 解释范围

这些是现在固定的新探索规格，不是原研究事前注册。个人饮食得分与餐次来自重叠观察窗，不称长期先验饮食。A 调整的是平均餐次特征，不能称同一种标准餐；B 是控制餐次能量及背景条件下的线性斜率差，既不是碳水自由添加试验，也不是生理碳水耐受性测量。NOVA4 的个人占比与上一轮餐次 NOVA4 暴露不同。rEDIH 沿用已反向和调整的原值，不再次翻转。AHEI/AMED/EAT13为项目改良版本，碳水占比不是健康指数。

完整七评分个人固定效应主效应不可识别，不能简单将旧 NOVA4 自变量换成个人评分；因此使用上述 A/B 两种可识别问题。一次性扩展所有菌种不是本包的目标，先把七评分与餐次反应的关联刻画完整。
