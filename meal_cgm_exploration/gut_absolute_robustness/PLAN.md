# Gut absolute glucose and meal-support sensitivity Implementation Plan

**Goal:** 按用户2026-10-04已确认方案，在独立目录完成四菌绝对餐后血糖与最低餐数/日期数敏感性分析，并提供最多三段终端摘要。

**Architecture:** 只读原`gut_meal_bridge_v2_20260929T044951_469958Z`已冻结的个人均值、成员和模型表。先核对哈希、资格、共同成员并复现原48项，再执行冻结的补充分析。新目录保存完整表、个体成员审计和三页聚合摘要；原数据、程序、结果不变。

**Tech Stack:** Python>=3.8，numpy/pandas/scipy；复用原HC3与分类变量编码。无新安装、无联网运行、不依赖两个window_qc目录或gut_same_visit_completion。

## 固定设计

- 人群仍为原四菌共同样本，primary_common及重叠strict_common；菌采样先后不作筛选。继续继承所有原合格餐规则及原CLR-Z。不扩大原共同完整人群，不补齐被原来源排除的人。
- A：`absolute_post_mean = baseline_glucose + mean_increment`，由相同合格餐的个人均值计算。三个结局Pre、Net、Abs使用相同X（原餐前模型的背景、饮食、餐营养和情境调整；不含餐前水平或斜率），每样本4菌×3结局=12项，固定BH q_panel12。总24项中8项Pre为原参照的复现，不称24项独立新发现。原调餐前的Net模型不替换。
- A：直接拟合三个结局的HC3区间；检验同X下βAbs=βPre+βNet仅作程序代数核对，不相加原不同调整集系数、不加CI、不算中介比例。Abs指0–120分钟曲线平均绝对水平，不是单独120分钟读数。
- B：固定5餐/3天、10餐/5天、20餐/7天；同时限制合格餐数和不同日期数。仅筛人，保留入选者全部原合格餐和已冻结个人均值。每门槛、每样本四菌×三个原餐次结局=12项。5/3复用原24项，另两个门槛新增48项。原调整集保持不变；各组原Net家族4项、Pre+Peak家族8项，另报q_meal12。
- A与B均为看过既有结果后新增的探索/敏感性分析，不能称原研究预注册。所有候选、阴性及NE保留。各门槛人群和strict重叠；各家族q不宣称控制跨所有门槛/样本的整体FDR。
- 不使用两周5%门槛；不重算CGM、饮食评分和原标准化。不加菌交互、全菌群筛选或中介分析。

## 实施任务

1. `inputs.py`：模块及依赖指纹、原来源状态/版本/五个结果文件哈希；验证ID、计数、strict标记、完整变量、来源样本与模型成员一致性。CSV保留字符串身份及数值round-trip精度。
2. `analysis.py`：原48项效应/SE/CI/p/q及成员复现门控；A24项、B72项（含原24项参照）、8项代数核对；门槛流失表、保留/排除者描述与SMD，NE保留既定分母。
3. `reporting.py`：三段摘要（来源/流失、A、B），全部效应/CI/q保留；完整表和未估计原因存服务器；`--show latest --page 1/2/3`只读重看，校验结果哈希，最新失败不回退旧成功。
4. `run_analysis.py`：原运行只读；独立时间戳目录，禁止写入原运行、覆盖已有结果或嵌套已有运行；记录spec、输入哈希、软件版本、完成/部分/失败状态；捕获中断并保留失败说明。
5. `tests/test_analysis.py`：阈值包含边界、只筛人不改均值、strict嵌套、分类编码与前导零ID、HC3独立矩阵参照、代数恒等式、来源复现、FDR/NE、输入变动拒绝、输出保护、三页无个体标识及原文件不变。增加独立上传布局/pheno命令行冒烟测试与Python3.8语法检查。
6. `README.md`、`上传说明.txt`、`METHODS.md`、`REVIEW.md`及`MANIFEST.json`：明确新/旧调整集、q家族、单位、源文件路径、直接运行/分页命令、合成检查与真实服务器运行的区别。
