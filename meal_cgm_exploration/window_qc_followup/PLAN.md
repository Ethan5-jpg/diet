# 同访视窗口与两周记录质量：2026-10-04固定方案

**Goal:** 检查CGM和饮食记录缺失，并在预定质量阈值下接续饮食、候选菌与餐次表型的关联分析。

**Architecture:** 新模块只读成功原meal、seven_diets、nutrition_bridge及gut_meal_bridge_v2运行；复用冻结模型与评分。先复现原模型，再在独立输出中应用固定质量规则。所有代码、依赖、输入及结果有SHA256；SQLite以immutable只读打开。

**Tech Stack:** Python>=3.8；现有numpy/pandas/scipy/pytz；标准库sqlite3。沿用服务器pheno环境。

用户在本次对话授权新建分析包、实现、验证并交付服务器运行。当前直接完成，不创建新聊天、不委派代理，不修改旧代码或结果。旧交接文档中的历史任务限制不作为本次指令。

## 研究定位

老师确认菌群、饮食和CGM属于同一访视测量窗口。本轮允许菌群日期在CGM结束后，不按先后排除，不称基线预测，也不开展因果中介。旧分析实际上已完成四菌直接关联；新增内容是整段记录质量审计及质量筛选后稳健性，而非把旧阴性结果重写成新发现。四菌由同队列旧结果选择，不能作为独立验证。

## 质量定义（在新结果产生前固定）

1. CGM计划14×24小时、15分钟一次，共1344槽，半开区间[start,start+336h)。缺失率=(1344-有效唯一槽)/1344。记录缺槽、无效/冲突槽分开。首部、尾部、内部和整段缺失为互斥的位置分类，合计等于总缺失；没有有效读数时整段缺失=1344、其余三个位置分类=0。既有valid标记和40–500 mg/dL规则沿用；不插值填补缺失。
2. 槽以start为起点。设备15分钟刻度的相位固定取首条时间戳，再映射到计划槽；允许相位刻度偏差180秒，不能假设激活时刻恰好是设备采样刻度。同值重复只计一次；同槽冲突或任一无效读数保守地使槽失效。多传感器不拼接，不选缺失率最低者。
3. 默认start=该连接首条可解析时间戳（含血糖无效读数），明确标FIRST_RECORDED_POINT_PROXY。它补计尾部缺失，但无法恢复第一条记录前的丢失；不能称核实的激活时间。可提供--window-starts：participant_id,cohort,research_stage,connection_id,planned_start（有时区时间戳），可选diet_start_date。显式表中未匹配的连接不能进入QC分析；原始行数如实统计，窗口无法确定时缺失率为NA，只有已知窗口完全无读数才计100%。
4. 饮食默认以CGM start的当地日期起，连续14个当地日历日期为分母。若提供diet_start_date则按该明确日期。日期有daily metadata.food_items>0且原缓存有实际事件、metadata与事件时区均一致，才算有记录。首日可能不完整，末日范围可能与336h边界不同，明确输出，不声称完全同步的14个完整日。另报CGM窗口内完整日的饮食覆盖；不以total_logging_days代替共同窗口日期。
5. 饮食率=(14-有记录日期数)/14，仅度量无记录日，无法识别同日漏餐。<5%要求14/14；<10%至少13/14；<20%至少12/14。不用条目数、热量或显著性推断完整饮食。日期缺失、时区异常及日表/事件不一致单独报告；无法解析时间的访视不能通过质量资格。
6. 主方案CGM和饮食均严格<0.05；敏感性均<0.10、<0.20。另做strict（明确糖尿病/A10为0）下<0.05。用户可在结果前通过--diet-main-threshold 0.10确定混合主阈值，配置保存在analysis_spec.json；不是按结果自动切换。
7. QC以参与者所分析的同一连接连接资格，不合并连接。进入模型的餐要求餐前30分钟起点>=CGM窗口起点、餐后120分钟终点<CGM窗口结束，且餐日期属于14个饮食参考日期。先在全部原餐次固定observation_day等时间特征，再筛选；餐数、日期数和碳水变化支持按旧模型规则重新检查。

## 固定分析

- **复现:** 原seven primary_available的42模型和gut的48模型，校验status/N/成员哈希/估计/SE/CI/p/q。未通过不开展新的效应模型。
- **饮食:** 主质量、strict主质量、10%、20%每组七评分×两结局×A背景/A餐食调整/B交互=42规格。每组沿用三家族各14检验；另给q_all42。原Z尺度不在筛选人群中重标准化。所有评分都保留，不只选显著者。
- **菌群:** 主质量、strict主质量、10%、20%每组四菌×三餐次结局+三整体CGM参照=24规格。沿用4/8/12家族，另给餐次q12及每组q24。HC3、残差自由度t区间，个人等权。整体CGM参照是原连接冻结指标，可能包含固定336h之外读数，明确作为参照，不伪称重算的两周指标。
- 只有主质量设置作为本轮主分析，其他为重叠样本敏感性；同时提供全部规格q值，家族内FDR不等于整个研究探索过程的校正。CI为逐项95%CI。
- 记录筛选人数/餐数、来源复现、保留/排除人群年龄/BMI/评分/餐数等差异和标准化差异。不能把质量筛选后效应变化解释成机制或独立复制。
- 样本不足或共线模型保留NOT_ESTIMATED及原因，NE以p=1保留计划FDR分母，其q显示NA；不降低质量阈值补足显著性。

## 实现与验证步骤

1. inputs.py核对新包、依赖、成功运行、冻结缓存及评分/菌群，加载日表和可选计划窗口；验证重复键、无时区计划、哈希变化。
2. coverage.py对缓存完整目标访视人群逐连接计算有效槽、首尾和内部缺失、最长缺口、14日饮食及完整日覆盖，输出private明细与聚合流失表。
3. analysis.py复现旧模型，然后预定质量四设置，保留全部模型、多重校正与成员哈希，报告样本选择差异。
4. run_analysis.py及入口完成check/audit/all/show、不可变来源、失败状态、新输出目录保护；终端只显示聚合结果。
5. 测试覆盖完整/提前结束/整日空缺、5%边界、重复冲突、无效值、离格、多连接、14日饮食分母、DST、窗口外餐、显式计划未匹配、原模型复现、空样本、失败show和合成端到端。Python3.8语法检查，旧相关模块回归测试。
6. 交付README、方法来源、复核记录、MANIFEST及ZIP；真实结果状态明确为尚未服务器执行。
