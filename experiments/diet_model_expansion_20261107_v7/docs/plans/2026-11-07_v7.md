# V7 实施与检验计划

实施状态：代码已完成，本地合成及上传目录模拟通过；实际检查范围见 `../../research_records/VALIDATION.md`。尚未运行真实服务器实验。

目标：固定发现集 `fiber_density → D_Glu`、原始单位与 v4 的两套家庭五折，在 v6 最优融合约 0.115 的基础上，检查新的表示和结构是否增加样本外预测信息，同时保留显式交互的独立评价。0.2–0.3 是期望，不是验收时可以通过调整结局、样本或验证方式保证的数字。

## 实验设计

共 30 条新管线、67 组内层候选设置。复用 v6 的只读数据适配器和 v4 预处理，不改动旧代码。外层家庭验证仍为两轮五折；每个外层训练集内重新做三折家庭验证。内层目标预处理、CLR、表示变换、筛选、PLS、聚类和模型全部只拟合对应训练角色。内层使用按样本数加权的 pooled MSE；外层报告 pooled OOF R²，不取五折 R² 的简单平均。

1. LightGBM：host、oral、gut、balanced 四种视图，覆盖叶子生长与逐层树的差别。
2. EBM：逐特征加性提升，以及只开放饮食线性项×肠道菌的显式交互版。
3. Hellinger 与 presence：检测 CLR 以外的组成表示。Hellinger 是训练参考集合内的相对丰度开方；树对单调变换不敏感，不能把开方本身解释成新的生物信号。
4. Taxon GAM、随机树嵌入、PLS→SVR：分别探索单菌非线性、无监督树划分和监督低维非线性。
5. 二阶低秩因子分解：共享低秩乘积项，缓解直接穷举所有交互的参数量。
6. Host residual trees：先拟合宿主/饮食线性部分，再用菌群拟合训练残差。
7. Hellinger 距离 Nyström：固定规模的核近似。
8. Gut mixture：训练集肠道 PC 的软聚类作为局部专家权重。
9. Block additive boosting：宿主/饮食、口腔、肠道分块回拟，作为明确不含饮食×菌群的匹配基线。
10. PC 交互与软门控交互：在同一已选择分块基线和同一肠道 PC 信息上增加乘积项；保留零交互候选。
11. Inner selector、凸融合、固定惩罚 ridge stacking：只使用外层训练集的内层 OOF 预测选择或组合。

oral 与 balanced 各自筛选；balanced 对口腔和肠道分配相同上限，避免肠道维度更多而挤掉口腔信号。总 R²、相对 v6 fusion 的差值和显式交互相对匹配 null 的 ΔR² 分别报告。EBM 对比保持训练设计和主项设置相同；允许全模型重估主项。PC/gate 对比保持基线预测固定，仅增加残差乘积项。

## 工程安排

- 新目录独立运行、独立 run-id；旧 v4/v6 仅只读引用，v6 fusion 不进入训练或选权。
- 每个内层候选独立完成检查点，存于服务器本实验 `runs/<id>/TRE_ONLY/`；哈希校验、运行锁、恢复时严格匹配代码/数据/环境。
- 使用 tmux 的真实终端承接输出，避免 v6 出现的 FUSE 长时间打开日志文件问题；不重定向长开日志。
- English/ASCII 服务器输出；短报告默认只列关键模型、三条交互和完整性状态。所有候选、警告及完整结果留在服务器。
- 新依赖装入本模块的隔离 venv，继承原 pheno 数值环境；LightGBM 固定 3.3.5 的 Linux manylinux1 wheel，避开 Amazon Linux 2 不支持的较新 glibc 要求。

## 验证清单

实现后先静态检查与格式化，再用冻结预处理源码的合成数据检验：FM 梯度、各模型拟合/预测/序列化、EBM 贡献分解、交互零候选与匹配基线、聚类训练边界、外层标签隔离、训练/验证特征隔离、融合权重、完整两轮五折流程与断点恢复、校验和/锁/不完整报告行为。最后在只含必要旧源码的上传模拟目录重跑，验证新文件夹可独立上传。真实队列不在本地运行；性能结论必须等服务器结果。

## 解释边界与后续

这里的外层划分已经被 v1–v6 开发使用，因此新结果仍是发现集开发结果；两轮重复共享参与者。成员报告提示肠道采样多在 CGM 后，不能将交互预测增益直接写成因果或前瞻个体饮食响应。换结局、餐次响应、功能模块等属于另一个预先定义的问题；本批次不偷偷换问题以追求 R²。

若本批次仍约 0.1，则先检查可用信号、时间对齐、测量误差和科学结局是否适合“相同饮食不同响应”，而不是无限扩大模型搜索。TabPFN、深度多组学大模型和 GPU 方法暂不列入本批：当前 CPU/系统兼容、样本量和可审计性条件下代价较高，不能保证改善。
