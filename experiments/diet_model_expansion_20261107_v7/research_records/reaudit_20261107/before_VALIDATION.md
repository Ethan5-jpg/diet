本记录仅涉及代码正确性和合成数据测试，**不包含 v7 真实 R²，也未访问服务器、下载参与者数据或启动服务器任务。**

## 实际通过的检查

1. **20 项自动检查全部通过**，原目录和上传目录模拟均通过。原始输出见 `validation_tests.txt`、`upload_simulation_tests.txt`。
2. 全部 **67 组正式候选参数**在同一训练/验证角色的宽合成数据上完成拟合与有限预测检查：原始合成数据为 360 人，口腔 144 列、肠道 176 列，包含零丰度。这里保留正式树轮数、PLS 维数、FM 迭代等设置。
3. 完整两轮五折、三折内层、三种融合、交互基线、部分运行→恢复→完成→报告均通过。**全流程测试使用缩小网格和迭代次数以验证控制流；正式参数的覆盖来自上一项单角色检查**，没有冒充本地已完成真实规模训练。
4. 改变外层验证标签后，全部新管线的选择、预测及融合权重保持相同；改变验证菌群特征后，训练表示、筛选与 PCA 状态不变。
5. FM 梯度通过数值差分，预测与显式逐对乘积展开一致。凸融合通过已知权重解和单纯形约束检查。软聚类权重归一且预测不重拟合门控。
6. EBM 逐项贡献求和与模型预测一致；显式成对贡献对比可计算。PC 交互 modifier 与有限变化一致；零交互精确退回对应 null。分块加性基线的饮食对比不随菌群画像改变。
7. 全部候选接口的预测形状、有限性与序列化重载检查通过。额外以 4 线程参数检查 LightGBM、EBM、随机树嵌入，均完成且未记录拟合警告。
8. 独占锁、恢复身份、源码/输入哈希、收据损坏拒绝、不完整结果不输出 pooled R²、未启动报告不创建目录、负 R² 保留、pooled 而非平均折 R²、跨折家庭重复拒绝均通过。
9. V6 参考读取用伪造的已完成合成文件检查：读取前后文件哈希不变；行、目标、校验和不匹配时拒绝使用。不读取真实 v6 参与者文件。
10. Ruff 静态与格式检查、shell 语法检查通过。运行代码、配置和短报告使用 ASCII，无 Python 内建参数化泛型注解。

## 上传模拟

在一个独立临时目录重建服务器的 handoff 文件结构，只放新 v7 文件夹及必要的旧源码，没有 `inputs/`，20 项测试仍通过。最终代码文件和该模拟目录的对应文件已逐一核对哈希。

该检查验证可上传结构和旧源码依赖；不等同于已经在美国服务器、Amazon Linux 2 或真实数据上运行。服务器仍须执行 `setup.sh` 与启动时的自动合成检查。

## 环境与兼容性

- 本地隔离环境：macOS ARM64、Python 3.11，精确版本见 `validation.json`。
- 核心数值包与配置对齐：NumPy 1.26.4、SciPy 1.11.4、pandas 2.1.0、pyarrow 15.0.2、scikit-learn 1.4.1.post1；新包 LightGBM 3.3.5、Interpret Core 0.6.5。
- LightGBM 本地使用官方 3.3.5 源码编译的无 OpenMP 版本；服务器使用同版本 Linux x86_64 wheel。**没有把 macOS 运行说成 Linux 实测**。4 线程参数检查不能替代服务器原生 OpenMP 检查。
- 已读取官方 Linux wheel 并核对 SHA256，扫描符号版本最高 `GLIBC_2.14`、`GLIBCXX_3.4.19`；Interpret Core 所带 Linux x64 原生库扫描最高 `GLIBC_2.4`。这是兼容性筛查，不是服务器动态链接实测。
- tmux 启动参数按旧版手册调整，避免 `new-session -c` 和 `=session`。启动命令构造、冲突拒绝与不使用文件日志通过模拟子进程检查；**本机未安装 tmux，未实际连接 tmux 会话**。

发布文件与手册：[LightGBM 3.3.5](https://pypi.org/project/lightgbm/3.3.5/#files)、[Interpret Core 0.6.5](https://pypi.org/project/interpret-core/0.6.5/)、[tmux 1.8 原版手册](https://github.com/tmux/tmux/blob/1.8/tmux.1)。
