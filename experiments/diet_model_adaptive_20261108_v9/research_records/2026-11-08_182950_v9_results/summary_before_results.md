# v9 实验设计与验证说明

## 当前状态

本批位于 `experiments/diet_model_adaptive_20261108_v9/`，为用户手动上传服务器运行准备。共有 **64 条模型流程、164 组内层候选设置**，其中包含 48 条基础流程、4 条匹配显式交互和 12 条融合或选型流程。本地只用合成数据检查，不读取或下载服务器真实数据；真实 R² 结果尚待运行。

主问题继续为人级 **纤维密度 → D_Glu 平均血糖**。沿用原来的评价样本准入、原始 mg/dL 单位和两轮家庭五折，每个外层训练集再做家庭三折调参。既有 v6/v7/v8 的预测仅在当前训练和选型结束后读入作对照，不进入新模型训练。

## 这次为什么这样设计

v8 已完成的服务器截图显示，原输入的 `ridge_wide` 两轮 R² 为 **0.120396／0.122745**；加入 UPF 分支的 `ridge_joint` 为 **0.120803／0.121851**。四种新显式交互在 40/40 次外层选型中关闭；FM 无已报告的拟合警告，但平均凸融合权重很小。前五条非融合流程仍在约 0.11。已有条件家庭区间一轮跨零，增益仍是发现阶段的线索。

因此，本批主要拓展三类问题：怎样更合适地表达稀疏菌群；多种预测器是否适合不同的人；已有日级饮食能否提供个人均值之外的信息。这些都是待验证的候选方向，不能因为方法更新就预计 R² 必然到 0.2–0.3。

## 模型覆盖

| 方向 | 本批实现 | 相对既往的主要区别 |
|---|---|---|
| 零值感知 | 菌是否检出、检出后的正丰度分别形成特征；另试 log1p 稳定化 | 同时保留存在与正丰度信息，并在训练折尝试更低的流行率阈值 |
| 组成对数比 | 稳定参考菌群的对数比，接 Elastic Net/CatBoost | 相对参考直接形成特征，提供不同的相对组成坐标 |
| 有监督多尺度平衡 | 按训练宿主残差关联构建正负菌群的几何均值比，接 Ridge/HGB | 压缩关注训练结局关联，同时保留对数对比结构；不是完整 selbal 算法 |
| 稀疏 rCLR | 非零丰度对数中心化、固定预算低秩补全、掩码投影 | 直接考察稀疏组成的几何；训练和验证走同一投影，不把缺失补全后的训练分数直接混用 |
| 生态汇总 | 丰富度、多样性、优势度、精确菌种 ID 对齐的口肠相似性，以及与局部 CLR 的混合输入 | 把容易在大量单菌中被淹没的整体结构显式提供给模型 |
| 分布与树结构 | Ordered/叶式 CatBoost、Tweedie 提升树、训练折 Gaussian 结局变换 | 拟合方式和损失不同，最终都回到原始血糖单位计算误差 |
| 轻量神经模型 | 两个隐层的残差网络；深层随机特征加岭回归输出头 | 两类结构都用原输入的紧凑表示；不依赖新增 GPU 框架，随机性和计算预算固定 |
| 个体化融合 | 正则化 softmax 权重门控、二级树模型、多项式融合 | 在当前外层训练集的内层折外预测上，检验不同人是否适合不同预测器 |
| 日级饮食扩展 | 能量和纤维的波动、分位数、非线性平均、相关性与周末差异 | 增加均值之外的记录信息，单独标记为 D 分支，与原输入比较 |

保留 HGB/CatBoost 强基线，帮助判断新表示是否有用。较广模型池与核心模型池均有固定凸融合及岭融合对照。softmax 门控有三个预设正则强度；其先验混合当前全局凸融合权重与少量均匀权重，使全局权重较低的模型仍有机会对部分人有用。

## 新增饮食信息的边界

只读取 handoff 中已有的 `inputs/daily/food_days_discovery_TRE_ONLY.parquet`，明确投影身份键、日期、能量、纤维和有效性标记。不会读取日级血糖表、`Y_value`、评分或预测列。

身份按 participant_id、cohort、research_stage 三项对齐，规范化日期后检查一人一天唯一。每人至少三个有效纤维日才计算该分支的分布特征；缺失信息用当前训练角色的中位数插补，并加缺失指示，不因此删除原评价样本。记录天数与个人均值对齐差只用于审计，不直接作为新增预测变量。

主暴露仍是原来的纤维密度，主结局与样本仍保持原口径。D 分支回答“新增饮食记录信息是否改善预测”，应与原输入模型分开解释。`daily_cat` 与 `ecohybrid_cat` 使用相同候选设置作新增信息的配对比较。覆盖人数和均值对齐情况会写入服务器注册记录，并在加载时打印。

## 显式交互与总体预测分开评价

本批有平衡特征及生态特征的口腔、口肠联合四条显式交互。对照均为已含相同菌群主效应的岭回归；仅新增正交化的饮食乘积修正，并试比 v8 更弱的惩罚路径，保留零交互候选。每条结果同时给出主效应对照 R²、交互 R²、匹配 ΔR²，以及选择关闭和活跃的外层折数。

个体化融合或神经模型可能包含隐式交互，但它们整体 R² 提高并不能单独证明“菌群修饰了饮食反应”。现有观察性访视数据也不自动提供干预反应的因果标签。报告中的 10→15 g/1000 kcal 修饰对比是模型关联量，单位为 mg/dL。

## 控制选型与信息泄漏

所有筛选、秩变换、伪计数、参考选择、平衡权重、低秩表示、缩放、插补、结局变换及神经训练都只使用对应训练角色。融合只用当前外层训练家庭的内层折外预测；门控使用确定的宿主/生态特征，不把不同内层折的 PCA 轴直接拼作同一坐标。

验证数据改变时，已拟合的门控可以产生不同权重和预测；这正是个体化的作用。检查要求的是其训练参数、内层选型和学到的函数不因此变化。原始预测器、门控与对照均按家庭隔离；最终每个外层的人员行和处理后结局须与冻结 v4 参考逐项匹配。

每轮 R² 由完整外层折外预测合并计算。目标达标必须是同一流程在两轮都达到阈值，以未舍入数值判断，保留负结果与警告。已有多轮发现集探索带来的适应性偏差不会因本轮嵌套调参自动消失，后续仍需独立确认。

## 运行、结果与验证

服务器代码、配置和输出均使用英文/ASCII，本地总结使用中文。仍在用户当前终端前台运行；环境安装在服务器原生路径 `/home/ec2-user/.venvs/hpp_v9_20261108`，避免 FUSE 项目目录的符号链接问题。可以在版本匹配时复用 v8 环境。没有外部预测 API，也没有自动下载预训练模型。

候选、选中对照、融合拟合和外层结果分别有校验和检查点。源码、配置、依赖、输入和线程数不变时可以续跑；旧锁不会自动清除。完整汇总和个人级产物留在服务器，只需截图短报告。默认输出少于 40 行，D 标记新增日级饮食信息，W 标记拟合或参与融合的成员警告。

本地验证包括：全部 164 个默认候选在稀疏合成宽表上的拟合、预测和序列化；神经及门控解析梯度；已知模拟非线性和分人群最佳模型的恢复；组成尺度不变性；掩码投影的独立计算核对；食物身份键和允许字段；原生单位的匹配交互；外层标签/特征扰动；真正运行入口的完整两轮流程、停止续跑、损坏检查点及报告恢复。

默认设置的小型候选检查与缩短预算的完整流程检查范围不同。它们验证代码行为，不产生真实 HPP R²，也不能替代 Linux 服务器预检。最终实际检查数量、耗时、环境和源码校验见 `research_records/validation.json`。方法来源和完整启动/报告命令见 README。

本地最终整套检查实际为 **32 项，全部通过，耗时 159.472 秒**。执行环境为 macOS ARM64、Python 3.11，七项数值依赖与配置锁定版本一致；语法、Ruff、安装脚本与依赖兼容性检查通过。旧 v6/v7/v8 的 **34 个 Python 源码文件**校验和保持不变。配置文件仅压缩排版，已核对全部设置不变。上传包另附逐文件校验清单。
