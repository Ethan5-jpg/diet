# Extension sensitivity Implementation Plan

**Goal:** 补齐全部 60 项扩展检验的六组敏感性，在独立运行中保留全结果和固定校正分母，衔接已完成的真实服务器运行。

**Architecture:** 新建独立入口，复用未修改的输入检查、OLS HC3 和拟合引擎。内部把七饮食全部纳入引擎敏感性网格，输出时恢复原 focus／extension 身份，并把共同样本明确改名为 common_all7_sample。独立输出目录、manifest 和最新指针，不覆盖原运行。

**Tech Stack:** Python 3.8+，既有 NumPy、pandas、SciPy、Matplotlib；本地 pytest 和既有合成输入。

用户已要求“补一下”并授权本地实现后上传服务器，不再增加设计批准步骤。工作区没有 Git／AGENTS.md，不创建无关 worktree 或提交；本任务直接实现和验证，不委派子代理。

## 设计决策

- 只重跑原显著 19 项会缩小验证与校正分母，因此不采用。
- 只拟合扩展 60 项虽较省计算，但无法沿用原 84 项整体校正，因此采用完整 84 项 × 7 设定 = 588 项；扩展占 420 项，其中 360 项是新增敏感性。
- 六组为 strict、protocol_same_sample、protocol_adjusted、quadratic、covariate_interactions、common_all7_sample。前五组定义不变；最后一组要求七饮食、四菌、三结局及各饮食协变量全部完整，区别于旧的两饮食共同样本。
- 每设定 q_all84 为固定 84 项 BH，失败／跳过项以 p=1 留在分母，自身 q 留空。原重点 24 项 q_focus24 单独保留，不能混称 q_all84。不为原 19 项重新校正。
- 原 19 项由已核验的旧运行 primary／extension／q_all<0.05 冻结，仅作为稳定性追踪集合。全 60 项扩展结果均输出；新显著者单独计数，不补进原 19 项。
- 样本、原 Z 尺度、协变量、结局单位、逐项区间与非因果边界沿用既有方法。补充是在看过主结果之后提出的同队列敏感性，不称预注册或独立验证。

2. 新建 `interaction/extension_reporting.py`：全部 588 项、扩展 420 项、条件斜率、样本流、校正家族、复现核对、逐设定稳定性、原阳性追踪表；三个紧凑截图摘要及包含全部扩展阴性结果的森林图。
3. 新建 `run_extension_sensitivity.py` 和 `.sh`：默认模块上级 Data 根路径，真实运行显式指定旧运行目录；旧输出只读。新输出位于 `outputs_extension_sensitivity/`，失败记录原因，不覆盖成功指针；合成演示独立标记。
4. 新建 `tests/test_extension_sensitivity.py`：验证网格／BH 分母、共同样本真实为同一批人、原主分析及前五组重点复现、指纹漂移拒绝、缺失／失败不伪装成稳定、原阳性冻结不纳入新显著、路径迁移及完整端到端输出。
