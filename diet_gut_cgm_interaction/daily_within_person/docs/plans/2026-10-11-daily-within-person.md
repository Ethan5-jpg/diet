# Daily diet–gut–CGM Implementation Plan

**Goal:** 构建可整体上传、从服务器原始记录生成全天日级面板并检验个人内饮食×菌群关联的独立模块。

**Architecture:** 所有新增运行代码位于 `Data/diet_gut_cgm_interaction/daily_within_person/`；不导入旧模块，不改写旧结果。沿用已知Data相对路径和最终CGM连接选择，分块读取原始日志、用运行目录中的SQLite缓存汇总每日数据，先做可行性检查，再运行固定的个人固定效应模型。每个新运行有独立状态、输入/代码指纹及三屏摘要。

**Tech Stack:** Python 3.8兼容语法，numpy、pandas、scipy、sqlite3；本地pytest及statsmodels作为独立数值核对工具。

## 已决定的范围

用户已直接授权完整实现，不另设设计批准关卡。采用原始CGM路径，是因为本地IGLU日表没有完整身份列；采用独立读取代码，是为了上传一个文件夹即可运行，避免依赖旧餐次运行目录及其代码版本。全部日级、个人级和缓存文件留在服务器，不生成ZIP，不自动制作论文图。

- 队列10k、00_00_visit；依据既有最终CGM表选择每人唯一connection_id，核对协变量表连接。
- 饮食：NOVA4已分类能量占比（每10个百分点）、纤维密度（每5 g/1000 kcal）。纤维等缺失不得当零；能量沿用已有4/9/4补算规则，记录补算量。
- 菌群：原T068/T096精确物种列及原CLR-Z；不按天数重复标准化。
- 结局：原始CGM按当地日期和15分钟格的观测中位数计算日Mean、SD、CV，无跨缺口插值；日SD不同于个人SDw。
- 主要4个交互检验为2饮食×2菌×日SD；全部12个交互另做BH。Mean/CV为解释性结局，不能作为独立重复。
- 7组模型：primary、明确无糖尿病/A10、严格记录覆盖、至少7天、营养背景、基线因素与饮食斜率交互、每人等权。每组保持完整预设家族，失败不缩小分母。
- 主模型至少200人、每人至少5个合格日，NOVA范围至少10个百分点或纤维密度范围至少2 g/1000 kcal。门槛是预先固定的设计规则，不是数据本身保证满足。
- 个人固定效应，CR1参与者聚类协方差含吸收固定效应自由度；给出原单位系数、完整区间、条件饮食斜率、样本流、变异支持和时间审计。
- 使用自报进食时间的操作性解释；无偏移时间不猜UTC。固定Asia/Jerusalem当地日，处理DST实际日长度；非该时区记录排除并计数。

## 实现步骤与文件

1. `config/analysis.json`、`daily/common.py`：冻结路径与规则，严格CSV、身份/数值/日期、指纹和原子JSON；先测试缺列、重复键、错误配置。
2. `daily/inputs.py`：参与者范围、唯一CGM连接、协变量排除逻辑、物种精确映射、可选取样日期审计；缺少真实字段直接报告，不猜身份。
3. `daily/build.py`：SQLite分块原始数据摄入；重复食物与时间异常保守排除；CGM重复同值合并/冲突失效；逐日完整性和暴露构建。测试跨块重复、午夜、DST、缺口、零与缺失、NOVA分母。
4. `daily/models.py`：加权/不加权去均值固定效应、CR1、预设家族、条件斜率、诊断、敏感性及失败保留。用显式个人哑变量OLS和statsmodels聚类协方差核对系数与区间；模拟已知交互、无个人内变异和秩缺陷。
5. `daily/reporting.py`、`run_analysis.py`、`run_analysis.sh`、`show_results.py`：check/build/analyze/all、独立输出、恢复核验、失败状态、三屏英文紧凑输出；不自动挑最新旧结果。
6. `daily/synthetic.py`、`tests/`：小型完整输入夹具，明确SYNTHETIC标记；跑端到端、恢复/防覆盖、源文件变更拒绝和搬到不同Data根的独立上传测试。
7. `README.md`、`METHODS.md`、`research_records/README.md`、`docs/LOCAL_VALIDATION.md`：完整服务器命令、研究边界、数据质量门槛、上传位置、本地验证与真实结果区分。

## 完成标准

独立文件夹可运行check和合成全流程；有意义的数值/数据质量测试通过；所有预设检验含失败行可追踪；无真实服务器数据时不声称真实队列通过。交付完整上传目录及一条全流程命令，运行后用户只需回传最多三屏摘要。
