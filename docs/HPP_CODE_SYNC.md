## 每次任务的同步顺序

1. 任务开始前确认目标目录、当前提交和服务器已有改动。
2. 在外部工作环境准备代码并完成相称的检查，将改动提交到 GitHub，记录完整 commit SHA 和变更文件。
3. 通过已登录的 AppStream 浏览器，将该提交对应的代码送入 HPP。
4. 在 HPP 暂存并校验内容哈希。先备份将被替换的文件，再同步明确指定的文件。
5. 根据任务运行语法检查、输入检查或正式入口，并查看实际输出。只有任务要求时才启动分析。
6. 记录代码提交、文件哈希、运行命令、退出状态、结果目录及备份位置。以校验与运行记录判断任务是否完成。
7. 如果运行时需要修复，再提交修复版本并重复部署核对，确保最终服务器代码与 GitHub 交付版本对应。
8. 阶段结束后，Codex 根据同一提交和回执独立复核；复核意见按新的代码任务处理。

GitHub 是代码版本记录；服务器回执记录实际部署和运行情况。保存文件或在服务器修复成功，不等于已经完成 GitHub 同步。

## 浏览器输入与终端查看

- 已验证的输入方式：AppStream 顶部 Clipboard → Ctrl+V → 显示 Pasted to remote → 远程终端 Edit → Paste。
- 长文本及含特殊符号的源码可压缩后以 Base64 传入，在服务器恢复，再校验 SHA256。这只是传输编码。
- 粘贴和运行后先等待画面更新，避免根据未更新的第一帧重复执行。
- 已实测可以上下滚动远程终端查看历史输出，并返回底部；重要输出应保存为日志，避免超过终端缓存。
- 当前终端没有可用的 git 命令；本流程不依赖服务器 git pull、SSH 或服务器安装 Codex。
- ZIP 下载和文件上传通道尚未验证成功；当前依赖的是源码读取和剪贴板输入。

提交号、任务目标、改动文件、输入输出约定、运行命令、退出状态、关键结果摘要和已知问题。复核关注统计逻辑、列名与路径、样本筛选、FDR 范围、结果可追溯性及是否存在意外重跑。
